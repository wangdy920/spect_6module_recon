# SPECT 多床位重叠区几何处理方案解析

## 1. 现状分析：用户当前的“裁剪拼接”逻辑

根据您的描述与示意图，您目前采用的是**“硬裁剪后拼接”**的策略。对于4个床位（假设单床高度为 $N_z$），其逻辑如下：

* **床位1 (End Bed)**：底部裁掉 16 (FOV边缘)，顶部裁掉 8 (拼接区的一半)。有效层数：$N_z - 24$。
* **床位2 & 3 (Middle Beds)**：顶部和底部各裁掉 8。有效层数：$N_z - 16$。
* **床位4 (End Bed)**：底部裁掉 8，顶部裁掉 16。有效层数：$N_z - 24$。

这实际上隐含了以下几何关系：

1. **物理重叠量 (Overlap)**：相邻床位实际上重叠了 $8 + 8 = 16$ 个像素。
2. **步进量 (Stride)**：床位移动的步长为 $N_z - 16$。
3. **边缘处理**：最两端的 16 个像素因位于视场边缘（灵敏度低或截断），被直接丢弃。

---

## 2. 改进方案：基于“加权融合”的同时重建

在同时重建（Simultaneous Reconstruction）算法中，我们**不再丢弃**重叠区的这 $8+8=16$ 个像素，而是让两个床位的投影数据在同一物理空间上**叠加**。这是提升图像质量的关键。

### 优劣对比

| 特性 | 现有方案 (硬裁剪) | 推荐方案 (加权融合) |
| :--- | :--- | :--- |
| **重叠区处理** | 丢弃一半数据 (Bed A 下半及 Bed B 上半被切除) | **全部保留**，Bed A 与 Bed B 的数据共同贡献于该区域 |
| **图像连续性** | 依赖几何对齐，可能存在明显的“接缝”或台阶效应 | **天然平滑**，灵敏度归一化自动处理交界处 |
| **信噪比 (SNR)** | 单倍统计量 (1x 数) | **提升 $\sqrt{2}$ 倍** (双倍计数) |
| **边缘处理** | 直接切除 | 包含在重建计算中，提供更完整的散射/衰减背景，**最后输出时再切除** |

### 几何计算公式

假设：

* 单床高度：$N_z$
* 重叠量：$O = 16$
* 床位数：$B = 4$

**推荐的全长重建高度计算：**
$$ \text{Total } Z = N_z + (B - 1) \times (N_z - O) $$

**以 $N_z = 128$ 为例：**

* 用户当前拼接总长：$(128-16-8) + (128-16) + (128-16) + (128-8-16) = \mathbf{432}$
* 推荐重建总长：$128 + 3 \times (128 - 16) = 128 + 336 = \mathbf{464}$
* **差异**：$464 - 432 = 32$，正好是首尾两端各 16 层的边缘区域。

---

## 3. 实施建议与代码变更点

为了支持上述逻辑，我们需要在代码中引入**重叠量 (Overlap)** 概念，并修改内存偏移计算。

| 模块 | 变更内容 | 详细说明 |
| :--- | :--- | :--- |
| **参数输入** | 新增 `-bedOverlap <int>` | 接受单位为像素的重叠量（如 16）。默认为 0。 |
| **全局尺寸** | 修改 `args.Nz` 计算 | `args.Nz = baseNz + (bedCount - 1) * (baseNz - bedOverlap);` <br>不再是简单的 `baseNz * bedCount`。 |
| **内存偏移** | 修改 `col_offset` | **旧逻辑**：`bed * baseCols` (相当于 Overlap=0)<br>**新逻辑**：`bed * (baseNz - bedOverlap) * baseNx * baseNy`<br>这确保了 Bed 2 的数据会写入 Bed 1 的顶部区域，实现物理重叠。 |
| **灵敏度** | 自动累加 | `computeSubsetSensitivity` 会自动将重叠区的灵敏度叠加（因为偏移后的地址是重合的）。无需额外代码，天然实现加权融合。 |
| **边缘裁剪** | 后处理 / 参数控制 | 建议新增 `-cropEnd <int>` 参数。重建时计算全长（464层），但在保存 `.mhd` 时，自动跳过首尾各 `int` 层（如 16），输出用户期望的 432 层。 |

### 示意图：几何映射

```text
全局 Z 轴 (Total Z = 464)
0       16      112     128     224     240     336     352     448     464
|-------|-------|-------|-------|-------|-------|-------|-------|-------|
<--Bed 1 (0-128)------->
                <--Bed 2 (112-240)----->
                                <--Bed 3 (224-352)----->
                                                <--Bed 4 (336-464)----->

[ 重叠区 ] = [112-128], [224-240], [336-352] (各 16 像素)
[ 边缘区 ] = [0-16] (Bed1首), [448-464] (Bed4尾) -> 建议最后裁掉
用户期望有效区 = [16 - 448] (长度 432)
```

## 4. 总结

针对您当下的方案，**最大的改进点在于利用 `bedOverlap` 参数来驱动重建引擎的内存映射**，而不是重建后拼接。
